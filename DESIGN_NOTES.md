# HealthTrack — The Follow-up Atelier: Design Notes & Visual System

**Product**: HealthTrack  
**Category**: AI-Assisted Patient Follow-Up Operations  
**Creative Direction**: *The Follow-up Atelier — Precision Clinical Operations with an Editorial Design Language*

---

## 1. Visual Concept & Design Philosophy

Most healthcare SaaS interfaces default to either generic corporate enterprise tables or consumer-oriented AI chatbots adorned with purple gradients, glassmorphism, and cartoon illustrations.

**The Follow-up Atelier** adopts a fundamentally different stance:
- **Clinical Instrument Precision**: The interface feels like a finely tuned operational tool for clinic coordinators and clinicians—grounded in quiet confidence, tactile clarity, and deliberate density.
- **Swiss Editorial Typographic Discipline**: Inspired by Swiss typographic systems, high-end medical monographs, and architectural blueprints. Whitespace, crisp rules, and hierarchy guide the eye rather than excessive rounded card containers.
- **Radical Provenance Transparency**: Instead of obscuring model operations behind ambiguous "AI Magic" badges, the interface explicitly itemizes the 5-point deterministic guardrail checks, displays whether a message was generated by the LLM or template fallback, and provides side-by-side original-versus-edited text comparisons.

## 3. Typographic Hierarchy

A distinctive editorial pairing establishes structure across operational density:

1. **Editorial Serif (`Newsreader` / Georgia)**:
   - Used for application branding, page headers, patient names, and primary section titles.
   - Conveys institutional permanence, thoughtfulness, and clinical seriousness.
2. **Interface Sans-Serif (`Inter` / system-ui)**:
   - Used for table data, draft editing textareas, action buttons, and explanatory labels.
   - Clean, highly legible at small operational sizes (12px–14px).
3. **Monospaced Data (`JetBrains Mono` / monospace)**:
   - Used for record identifiers (`APT-0001`, `PAT-0004`, `REM-0002`), timestamps, character bounds (`162 / 350`), and lifecycle badges (`7D ELIGIBLE`, `DRAFT`, `APPROVED`).

## 4. Architectural Highlights & Signature Workflows

### Signature Screen: The Follow-up Studio
Rather than a chat bubble interface, the studio is organized into an **integrated three-column workbench**:

```
+------------------------+------------------------------------+-----------------------------+
| COLUMN A: ENCOUNTER    | COLUMN B: MESSAGE WORKBENCH        | COLUMN C: VALIDATION        |
| - Patient Name         | - Patient Encounter Banner         | - Generation Provenance     |
| - Encounter Type       | - Generate / Regenerate Controls   |   (AI vs. Fallback Reason)  |
| - Encounter Timestamp  | - Patient-Facing Draft Editor      | - 5-Point Safety Audit      |
| - 7-Day Window Badge   | - Original vs. Edited Text Diff    |   (Length, Greeting, etc.)  |
| - Reminder State Tag   | - Active Character Bound Indicator | - Human Approval Actions    |
+------------------------+------------------------------------+-----------------------------+
```

1. **Step A — Encounter Queue**:
   - Operators can instantly inspect encounters, verify 7-day lookback eligibility (`[ref - 7d, ref)`), and select records awaiting drafting.
2. **Step B — Message Workbench**:
   - Directly triggers backend generation (`POST /api/v1/reminders/appointments/{id}/draft`).
   - Displays live character count against the 15–350 character bound.
   - If the operator edits the draft, the interface tracks `is_edited=true` and allows toggling a prompt comparison view (`"Compare with Original Draft"`).
3. **Step C — Validation & Provenance**:
   - Shows the exact generation origin (`Configured LLM Generated` or `Deterministic Template Fallback`).
   - If fallback was used, explains why in plain language (e.g. `Offline mode: No external LLM provider configured`).
   - Renders individual pass/fail badges for all 5 deterministic safety rules:
     - Length Bounds (15–350 chars)
     - Personalized Greeting
     - Non-Prescriptive Language (no medical advice, no medications)
     - Date & Time Consistency (no hallucinated dates)
     - Prompt & Injection Isolation (zero PII, zero prompt echo)
   - Prominently features the clinical notice: *Heuristic checks enforce structural hygiene, not clinical certification.*
   - Provides one-click human approval (`Approve Draft for Dispatch`) and rejection with immediate database persistence.

## 5. Other Operational Screens

1. **Overview**:
   - Leads with an **Attention Required** callout indicating how many drafts currently await clinician review.
   - Displays real database metric counts (registered patients, encounters, approved reminders, AI vs. fallback provenance split).
   - Lists the recent operational audit trail with direct links to inspect records in the Studio.
2. **Patient Register**:
   - Editorial record table with deliberate column widths.
   - Real-time search by patient name, synthetic email, or ID.
   - Modal form for registering synthetic patients with strict email validation.
3. **Appointments**:
   - Encounter schedule showing visit types, dates, and live 7-day window eligibility tags.
   - Filter to isolate eligible appointments.
   - Direct "Draft in Studio" shortcut from any encounter row.
4. **Delivery Log**:
   - Truthful transparency notice explaining that external SMS (Twilio) and email transport are disabled in safe demonstration mode.
   - Real transmission history table (zero fabricated "delivered" events).
5. **Settings & Integration Readiness**:
   - Displays live server configuration (active provider, model identifier, credential status, SQLite PRAGMA FK enforcement).
   - One-click "Clear All Clinical Records" for clean state testing.
